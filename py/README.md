# 双色球走势分析与智能选号工具

一套基于**真实历史开奖数据**的走势分析、号码生成与**策略回测**工具。零第三方依赖，提供命令行与 Web 两种用法。

## ⚠️ 先把话说清楚

**双色球每期开奖是独立的均匀随机抽样。任何算法都无法提高 1–4 等奖的概率。**

市面上所有"预测""必中"的说法都是错的。这个项目不打算骗你，它做的是三件诚实的事：

1. **唯一确定有效的手段：蓝球全覆盖。** 买 16 注、覆盖全部 16 个蓝球，**数学上保证每期至少中 1 注六等奖（5 元）**。这不是概率、不是运气，是必然。代价是成本 32 元、保底只回 5 元 —— 它提高的是**中奖率**，不是收益。
2. **降低撞号损失。** `spread` 策略避开生日号（1–31）与大众热号，`shape_filter` 剔除形态极端的组合。中奖概率完全不变，但真中了大奖时，**和你平分奖池的人更少**。这是唯一能真实影响"到手金额"的合法手段。
3. **一切结论用真实历史回测验证。** 内置走查式回测，你可以自己跑出来看，不用信我。

> 双色球整体返奖率约 50%，**长期 ROI 必为负**。理性购彩，量力而行。

## 快速开始

```bash
# 更新真实历史数据（带质量体检，体检不过拒绝写入）
python fetch_data.py 500

# ★ 保底模式：16 注覆盖全部蓝球，本期必中至少 1 注六等奖
python cli.py -n 16 -s spread --blue-cover --shape-filter

# 随机 5 注
python cli.py -n 5

# 走势摘要 + 历史形态统计
python cli.py --summary --shape

# 回测：用真实历史逐期验证配置
python cli.py --backtest -n 16 -s spread --blue-cover --periods 300

# 内置自检（8 项，含数据错列回归检查）
python cli.py --self-test
```

## CLI 参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-n, --count` | 生成注数 | 5 |

| `--shape` | 打印历史形态统计与过滤区间 | 关 |
| `--backtest` | 运行历史回测 | 关 |

## 算法说明

### 1. 走势指标
- **频率**：号码历史出现次数，越高越「热」
- **遗漏**：距最近一次出现的期数，越大越「冷」
- **冷热分档**：按频率三等分标记 热/温/冷
- **区间分布**：红球分 01-11 / 12-22 / 23-33 三区

### 2. 形态指标（单注特征）
| 指标 | 含义 | 真实开奖典型值（近 500 期） |
|------|------|------|
| 和值 | 6 红之和 | 均值 ~100，中间 80% 落在 74–127 |
| 奇偶比 | 奇数个数 | 3:3 最多，2:4 / 4:2 次之 |
| 大小比 | ≥17 的个数 | 3:3 最多 |
| 连号 | 相邻差 1 的对数 | 多为 0–2 对 |
| 跨度 | 最大－最小 | 中间 80% 落在 18–30 |
| AC 值 | 两两差值去重数 −5，衡量离散度 | 多为 6–10 |
| 区间比 | 三区各自个数 | 2-2-2 最常见 |

`--shape-filter` 会剔除落在这些区间之外的极端组合（例如 6 个号全挤在一区、AC 值只有 4）。

### 3. 选号策略
| 策略 | 逻辑 | 能提高中奖率吗 |
|------|------|------|
| `random` | 完全随机，等价机选 | 基准 |
| `hot` | 高频号加权 | ❌ 不能 |
| `cold` | 高遗漏号加权 | ❌ 不能 |
| `balanced` | 频率 × 遗漏综合 | ❌ 不能 |
| `zone` | 三区各取 2 个，锁定 2-2-2 形态 | ❌ 不能 |
| `spread` | 压低生日号(≤31)与热号权重 | ❌ 不能，但**降低撞号摊薄** |
| **`--blue-cover`** | **蓝球轮询覆盖** | ✅ **能，且是数学保证** |

加权抽样采用 **Efraimidis–Spirakis** 无放回加权算法。

### 4. 回测（走查式，绝不使用未来数据）
预测第 N 期时只用前 N−1 期数据重建分析器，再与真实开奖对奖。

近 300 期实测结果：

| 策略 | 注/期 | 蓝覆盖 | 期命中率 | ROI |
|------|------|--------|---------|-----|
| random | 5 | – | 30.0% | −70% |
| hot | 5 | – | 27.0% | −76% |
| balanced | 5 | – | 25.3% | −85% |
| spread + 形态 | 5 | – | 33.7% | −72% |
| balanced | 8 | ✅ | **49.7%** | −83% |
| balanced | 16 | ✅ | **100.0%** | −75% |
| spread + 形态 | 16 | ✅ | **100.0%** | −47% |

**读懂这张表：**
- 前 4 行的差异（25%–34%）全是**随机波动**，多跑几个种子就会互相反超，不代表任何策略更强。
- 覆盖 8 个蓝球 → 49.7%，几乎精确等于理论值 **8/16 = 50%**。
- 覆盖 16 个蓝球 → **100.0%**，一期不落。这就是数学保证。
- **所有 ROI 都是负的**，且必然为负。保底提高的是"中奖率"，不是"赚钱"。

## 🐛 一个必须记录的教训：数据错列

早期版本 `fetch_data.py` 用「第一个 1–16 之间的数字」当蓝球，但红球也可能 ≤16，结果**整份数据的蓝球列 = 最小红球**。

后果：蓝球分布严重畸形（1 号 54 次、14 号 1 次，而均匀分布应各约 31 次），回测显示 `hot` 策略"期命中率 44% 碾压 random 27%"，8 个随机种子全部一致 —— 看起来像铁证如山的有效策略，实际是纯粹的数据污染。

**定位过程**：发现红球命中均值全部贴合理论值 1.09，差异 100% 来自蓝球（hot 11.7% vs 理论 6.25%）→ 用合成的纯随机数据做对照实验，`hot` 优势完全消失 → 检查原始 CSV，确认 blue 列等于首个红球。

**修复与防御**：
1. 改为严格**按列位置**解析（`[0]`期号 `[1..6]`红球 `[7]`蓝球 `[15]`日期），并校验红球互异、值域合法
2. 新增 `sanity_check()` 数据质量体检：蓝球取值种类数、最大频次偏离度、**蓝球是否等于最小红球**、红球频率分布
3. CLI 与 Web 的数据刷新都**先体检再落盘**，不合格直接拒绝写入
4. `--self-test` 增加回归检查，防止同类 bug 复活

修复后重抓 500 期，所有策略的红球命中均值（1.06–1.11）与蓝球命中率（5.7–6.7%）全部回归理论值 —— 与"无法预测"的数学结论完全一致。

> 教训：**回测跑出漂亮结果时，第一反应应该是怀疑数据，而不是庆祝。**

## 作为库调用

```python
from ssq import generate_numbers, load_history, backtest

# 保底模式：16 注覆盖全部蓝球
tickets = generate_numbers("data/sample_history.csv", count=16,
                           strategy="spread", blue_cover=True, shape_filter=True)
for t in tickets:
    print(t.formatted())        # 04 06 09 20 31 32  + 13

# 自己跑回测
draws = load_history("data/sample_history.csv")
r = backtest(draws, count=16, strategy="spread", periods=300,
             blue_cover=True, shape_filter=True)
print(r["period_hit_rate"])     # 1.0
```
